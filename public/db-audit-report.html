🔴 Kritik #2 — Bozuk ShiftCode

22 Atamada ShiftCode Yerine Timestamp

assignments koleksiyonunda bazı kayıtlar shift kodu yerine JavaScript timestamp değeri tutuyordu. Bu kayıtlar çizelgede bozuk görünüm ve hesap hatalarına yol açıyordu.

❌ Önce — Tüm shiftCode değerleri
// Normal değerler:
  "N"   → 301 atama  ✓
  "V1"  → 134 atama  ✓
  "M"   →  52 atama  ✓

// BOZUK değerler:
  "1761072131831" → 13 atama ← Date.now()!
  "1761072131834" →  9 atama ← Date.now()!

// Toplam bozuk: 22 atama
Neden Oldu?

DutyRowsEditor bileşeninde satır ID'si (row.id) ile shiftCode karıştırılmış. Satır ID'leri Date.now() ile üretiliyor; bir noktada yanlış field atanmış.

✅ Sonra — Temiz veri
// Bozuk kayıtlar silindi
db.assignments.deleteMany({
  shiftCode: { \$regex: /^\d{13}$/ }
})
// → deletedCount: 22

// Kalan sağlıklı kayıtlar:
  "N"   → 301 atama  ✓
  "V1"  → 134 atama  ✓
  "M"   →  52 atama  ✓
// Toplam: 487 temiz atama
Uzun Vadeli Öneri

Backend'de shiftCode validation ekle: kayıt öncesi değerin tanımlı vardiya kodlarından biri olduğunu kontrol et.

🔴 Kritik #3 — AuditLogs Sınırsız Büyüme

12,815 Log — TTL Olmadan Sonsuza Büyür

Audit logları Mart 2026'dan beri birikiyor. Silme mekanizması yoktu. MongoDB Atlas'ın ücretsiz 512MB limiti 8-10 ay içinde dolacaktı.

Büyüme Projeksiyonu (öncesi)

Aylık ~1,900 kayıt → TTL olmadan:

Şu an (2 ay): 12,815 kayıt
6 ay sonra: ~24,000 kayıt
12 ay sonra: ~35,000 kayıt
24 ay sonra: ~57,000 kayıt
Atlas Free 512MB dolma: ~Ağustos 2027 
// Index analizi — önce
auditlogs indexes:
  _id
  requestId
  createdAt          ← sadece sıralama
  hospitalId+createdAt
  userId+createdAt
// TTL index YOK → sonsuza büyür
TTL Index Eklendi (sonrası)

90 gün sonra kayıtlar otomatik silinir:

Steady state: ~17,000 kayıt (90 gün)
Sabit kalır: Hiç büyümez
Atlas storage: Güvende ✓ 
// TTL index eklendi
db.auditlogs.createIndex(
  { createdAt: 1 },
  {
    expireAfterSeconds: 7776000,
    // 7776000 = 90 gün
    name: 'auditlogs_ttl_90d'
  }
)
// MongoDB her gece siler
// Bakım gerektirmez
