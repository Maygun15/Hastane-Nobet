🔴 Kritik #2 — Hardcoded Şifre

Sabit Şifre Fallback Kaldırıldı

TC numarası yokken "Hastane2026!" kullanılıyordu — tüm kullanıcılar aynı şifreyle açılıyordu.

❌ Eski Kod — users.routes.js
// quick-create endpoint
const tempPassword =
  (tc ? String(tc).trim() : '')
  || 'Hastane2026!';  // ← herkes aynı şifre!

// bulk-from-personnel endpoint
const tempPassword =
  p.tc || 'Hastane2026!';  // ← yine aynı!

await user.setPassword(tempPassword);
user.mustChangePassword = true;
await user.save();
✅ Yeni Kod — Rastgele Şifre
// users.routes.js başına eklendi
function randomTempPassword() {
  return crypto
    .randomBytes(10)
    .toString('base64url');
  // → "xK9mP2qR7vLw" gibi
}

// quick-create
const tempPassword =
  (tc ? String(tc).trim() : '')
  || randomTempPassword();

// bulk-from-personnel
const tempPassword =
  p.tc || randomTempPassword();
Neden base64url?

crypto.randomBytes(10) = 80 bit entropi → kaba kuvvet imkansız. base64url URL-safe karakterler üretir, özel char gerektirmez.

🟡 Önemli — Graceful Shutdown

Sunucu Güvenli Kapanıyor

SIGTERM (Vercel/Docker kapatma sinyali) alınca devam eden istekler bekleniyor, DB bağlantısı düzgün kapanıyor.

❌ Eskiden: index.js sonu
const server = app.listen(PORT, () => {
  console.log(`🚀 Sunucu :${PORT}`);
  // reminderService başlatma...
});

// SIGTERM yoktu — Vercel kapatınca
// istekler ortada kalırdı!
Neden önemli?

Vercel, deploy sırasında eski instance'a SIGTERM gönderir. Handler yoksa process anında ölür → devam eden DB yazma işlemleri yarıda kesilir → veri bütünlüğü bozulabilir.

✅ Yeni: Graceful Shutdown Handler
function gracefulShutdown(signal) {
  console.log(`[SHUTDOWN] ${signal}…`);

  server.close(async () => {
    // 1. Yeni bağlantı kabul etme
    await mongoose.connection.close(false);
    // 2. MongoDB'yi temiz kapat
    if (Sentry) await Sentry.close(2000);
    // 3. Sentry'yi flush et
    process.exit(0);
  });

  // 15sn timeout → zorla çık
  setTimeout(() => process.exit(1),
    15_000).unref();
}

process.on('SIGTERM', () =>
  gracefulShutdown('SIGTERM'));
process.on('SIGINT',  () =>
  gracefulShutdown('SIGINT'));

🔴 Kritik #3 — Log Temizliği

173 console.log Sorunu

Backend'deki console.log'lar production loglarında hassas veri sızdırabilir. Doğru yaklaşım structured logging.

❌ Sorunlu Örüntüler
// Kullanıcı verisi loglama
console.log('User found:', user);

// Request body loglama
console.log('Body:', req.body);

// Şifre hash loglama
console.log('Hash prefix:',
  hash.substring(0, 7));
Risk Nedir?

Vercel/Heroku log stream'leri varsayılan olarak açık. console.log ile TC, e-posta, şifre hash parçaları log sistemine yazılırsa hem KVKK hem güvenlik ihlali olur.

✅ Önerilen Yapı — logger.js
// utils/logger.js (örnek)
const LOG_LEVEL =
  process.env.LOG_LEVEL || 'info';

module.exports = {
  info:  (msg, meta) =>
    IS_PROD
      ? null  // prod'da sessiz
      : console.log(`[INFO]`, msg),
  warn:  (msg) =>
    console.warn(`[WARN]`, msg),
  error: (msg, err) =>
    console.error(`[ERR]`, msg,
      err?.message),  // stack değil!
};
Hızlı Kural

Boot logları → tamam. Hata mesajı → tamam. User objesi / request body / hash → asla. Sadece userId veya email gibi identifier logla.
